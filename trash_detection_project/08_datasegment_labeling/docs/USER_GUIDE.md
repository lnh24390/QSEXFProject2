# 사용 설명서 (User Guide)

DataSegmentLabeling 으로 라벨을 만들고 모델을 학습시키기까지의 전 과정입니다.

---

## 0. 첫 실행

```bash
uv pip install -r requirements.txt
python main.py
```

SAM 이나 학습 라이브러리는 **없어도 앱이 뜹니다** — 수동 폴리곤·박스 라벨과
가져오기/내보내기는 그대로 됩니다. 설치는 필요할 때
**도움말 → 선택 패키지 설치 상태** 를 보고 하면 됩니다.

처음 열면 프로젝트가 없습니다. 아래 순서로 진행하세요.

---

## 1. 시작하기

### 가장 빠른 길 — 이미지 폴더만 열기

**파일 → 이미지 폴더 열기 (Ctrl+Shift+O)** 로 이미지가 든 폴더를 고르면 끝입니다.
프로젝트를 미리 만들 필요가 없습니다.

- 폴더는 **어디에 있어도 됩니다** — 다른 드라이브, 네트워크 드라이브, 외장 디스크.
- **고른 폴더에는 아무것도 쓰지 않습니다.** 읽기 전용이거나 여러 사람이 공유하는
  폴더도 그대로 쓸 수 있습니다.
- `project.json` 과 라벨은 앱 폴더의 `projects/<폴더명>_<해시>/` 에 저장됩니다.
  같은 폴더를 다시 열면 하던 작업을 이어서 합니다.
- 하위 폴더까지 재귀적으로 스캔합니다.

### 폴더를 창에 끌어다 놓기 — 가장 빠름

데이터셋 폴더를 **창에 드래그해서 놓기만** 하면 됩니다. 열려 있던 프로젝트는
저장되고 그 폴더로 바뀝니다.

폴더 안에 있는 **이미지/라벨 쌍을 전부 찾아 한 번에 매칭**합니다 — 세트가
여러 개든(`set_a/ set_b/ set_c/`), train/val/test 로 나뉘어 있든 모두 열립니다.
구조는 알아서 판별합니다:

| 폴더 모양 | 처리 |
|---|---|
| `images/` + `labels/` | 각각 이미지·라벨로 |
| `images/train,val` + `labels/train,val` | 하위까지 훑어서 인식 |
| 이미지와 `.txt` 가 한 폴더에 섞임 | 같은 폴더를 양쪽으로 |
| 이미지만 | 이미지만 열림 |
| 이미지 + COCO `.json` | json 을 라벨로 |

라벨이 있으면 **검증 화면이 바로 뜹니다.** 구조를 추측한 것이므로 매칭 수와
미리보기를 확인하고 가져오세요. 라벨 폴더가 여러 곳이면 합산해서 보여주고,
폴더별 매칭 수도 함께 표시합니다.

> **파일 이름이 겹치면 경고합니다.** 라벨은 이름(확장자 제외)으로 짝지어지므로,
> `set_a/images/001.jpg` 와 `set_b/images/001.jpg` 처럼 이름이 같으면 한쪽
> 라벨이 엉뚱한 이미지에 붙습니다. 이럴 때는 파일 이름을 세트별로 구분되게
> 바꾼 뒤 다시 여세요.

### 이미지와 라벨을 함께 열기

이미 라벨이 있는 데이터셋이라면 **파일 → 이미지+라벨 함께 열기** 한 번으로
끝냅니다. 이미지 폴더 → 라벨 폴더를 차례로 고르면 검증 화면까지 이어집니다.

남의 데이터셋을 **확인만** 할 때는 **파일 → 이미지+라벨 열기 (열람 전용)**.
프로젝트가 임시 폴더에 만들어지고 **앱을 닫으면 지워집니다** — 앱 폴더에
아무것도 남지 않습니다.

라벨을 이미지 옆에 두고 싶거나 폴더 구조를 직접 정하고 싶으면 아래처럼
프로젝트를 만드세요.

### 프로젝트 만들기

1. **파일 → 새 프로젝트 (Ctrl+N)**
2. 프로젝트를 저장할 **빈 폴더**를 고릅니다.
3. 이름을 입력합니다.
4. **이미지 폴더**를 지정합니다.
   - 취소하면 `<프로젝트>/images` 가 만들어집니다. 여기에 이미지를 넣고
     **파일 → 이미지 추가** 를 쓰거나, 처음부터 기존 이미지 폴더를 지정하세요.
   - 하위 폴더까지 재귀적으로 스캔합니다.

생성되는 구조:

```
myproject/
  project.json        클래스 목록 + 이미지 목록
  labels/             이미지 1장 = JSON 1개
  labels/_index.json  통계 캐시 (자동)
```

## 2. 클래스 만들기

오른쪽 **[클래스]** 패널 → **추가**.

- 색은 자동 배정되며 **[색]** 으로 바꿀 수 있습니다.
- 이름 변경은 **[이름]** 또는 항목 더블클릭.
- **삭제** 시 그 클래스로 라벨된 도형도 함께 사라집니다(경고 후 진행).
- 라벨링 중에는 **숫자키 1–9** 로 빠르게 전환합니다.

## 3. SAM 모델 준비

**[SAM]** 탭 → **모델 관리자 (Ctrl+M)**

1. 상단에 이 PC 사양과 **★추천** 모델이 표시됩니다.
2. 원하는 모델을 고르고 **[다운로드]** (또는 **[추천 모델 받기]**).
   - 중간에 끊겨도 다시 누르면 **이어받기** 됩니다.
   - 파이썬 패키지가 없으면 필요한 `pip install …` 명령을 알려줍니다.
3. 닫고 **[모델 불러오기]** 를 누르면 상태바에 `SAM: … [cuda/fp16]` 이 뜹니다.

> 정밀도(fp16/fp32/bf16/int8)는 모델별로 지원하는 것만 나옵니다.
> VRAM이 빠듯하면 fp16, GPU가 없으면 int8을 고르세요.

## 4. 라벨링

왼쪽 목록에서 이미지를 클릭하면 캔버스에 열립니다.

### 4.1 SAM 클릭 (Ctrl+2) — 가장 많이 쓰는 방법

| 동작 | 키 |
|---|---|
| 객체 위 **포함(+)** 점 | 좌클릭 |
| 잘못 잡힌 영역 **제외(−)** 점 | 우클릭 |
| 후보 마스크 전환 | `[` `]` |
| 확정 (현재 클래스로 저장) | `Enter` |
| 취소 | `Esc` |

첫 클릭 때 이미지 임베딩을 계산하므로 잠깐 걸리고, 이후 클릭은 즉각 반응합니다.

### 4.2 SAM 박스 (Ctrl+3)

객체를 드래그로 감싸면 마스크가 생성됩니다. 작은 객체나 겹친 객체에 유리합니다.
`Enter` 확정, 필요하면 도구를 클릭 모드로 바꿔 점을 더 찍어 보정합니다.

### 4.3 수동 폴리곤 (Ctrl+4)

SAM이 잘 못 잡는 형태를 직접 그립니다.
좌클릭으로 점 추가 → **우클릭 또는 더블클릭**으로 닫기.

### 4.4 텍스트 프롬프트 (SAM 3 계열 전용)

**[SAM]** 탭 하단의 텍스트 칸에 `car`, `scratch` 처럼 입력하고
**[텍스트로 찾기]** 를 누르면 해당 개념의 인스턴스를 한 번에 잡아
현재 클래스로 모두 추가합니다. SAM 3 계열이 아니면 비활성화됩니다.

### 4.5 박스 라벨 (Ctrl+6)

드래그로 박스를 직접 그립니다. **한 이미지에 여러 개를 계속 그릴 수 있고**,
세그먼트와 섞어 써도 됩니다. 검출용 라벨을 손으로 만들 때 쓰세요.

- `Ctrl+3` **SAM 박스** 와 다릅니다 — 저쪽은 박스를 프롬프트로 써서 *세그먼트*를
  만들고, 이쪽은 박스 자체를 라벨로 남깁니다.
- 박스는 점선으로 그려져 세그먼트와 구분됩니다.
- 이미지 밖으로 나가면 경계에 맞춰 잘립니다.
- 나중에 마음이 바뀌면 `Ctrl+5` **박스→세그먼트** 로 SAM에 넘겨 마스크로
  바꿀 수 있습니다.

### 4.6 세그먼트 ↔ 박스 자유 변환

툴바의 **[세그→박스]** / **[박스→세그]** 버튼(또는 `Ctrl+Shift+B` /
`Ctrl+Shift+G`). 도형을 선택하고 누르면 됩니다. 여러 개를 한 번에 바꿔도 됩니다.

- **세그먼트 → 박스** — 폴리곤의 바운딩 박스로 바꿉니다. 원본 폴리곤은
  안에 보관됩니다.
- **박스 → 세그먼트** — 세그먼트에서 온 박스는 **SAM 없이 원본 그대로**
  즉시 복원됩니다(정점·구멍까지 동일). 가져온 라벨이나 손으로 그린 박스는
  SAM 이 마스크를 만듭니다.

> 왕복해도 원본이 상하지 않으므로, 검출용으로 박스만 필요할 때 잠깐 바꿔
> 내보내고 다시 세그먼트로 돌아와도 됩니다.

### 4.7 수정 (Ctrl+1 선택/편집)

| 동작 | 키 |
|---|---|
| 선택 | 클릭 (Shift+클릭 다중 선택) |
| 정점 편집 모드 | 도형 더블클릭 |
| 정점 이동 | 흰 핸들 드래그 |
| 정점 추가 | Alt+클릭 (가장 가까운 변에 삽입) |
| 정점 삭제 | 핸들 더블클릭 |
| 편집 되돌리기 | `Ctrl+Z` — 정점 이동·추가·삭제, 도형 이동까지 되돌아갑니다 |
| 도형 이동 | 도형을 잡고 드래그 |
| 삭제 | `Del` |
| 클래스 바꾸기 | ① [클래스] 패널에서 클래스 선택(또는 숫자키 `1`–`9`) → ② 캔버스나 [도형] 표에서 도형 선택 → ③ [도형] 패널의 **[선택 도형에 현재 클래스 적용]** |

### 4.8 마스크 → 폴리곤 품질 조절

**[SAM]** 탭의 *마스크 → 폴리곤*:

- **외곽선 부드럽게** — 마스크 경계의 1픽셀 계단을 펴서 외곽선을 매끄럽게
  합니다. 기본 2. 0이면 계단 그대로, 4 이상은 아주 작은 돌기까지 없앱니다.
  형태를 왜곡하지 않으므로 톱니처럼 보이면 먼저 이 값을 올리세요.
- **단순화(ε)** — 0에 가까울수록 윤곽이 촘촘합니다(점 개수↑, 파일 크기↑).
  기본 0.002. 부드러운 곡선 객체는 0.001, 직선 위주면 0.005 정도.
- **최소 면적(px)** — 이보다 작은 조각은 버립니다. 잡티가 섞이면 값을 올리세요.
- **가장 큰 덩어리만 사용** — 떨어진 조각을 무시하고 본체만 남깁니다.

### 4.9 보기 설정 — 도형이 잘 보이게

겹친 도형이 뭉개져 보이면 **보기** 메뉴에서 조절합니다.

| 항목 | 설명 |
|---|---|
| **외곽선만 보기** (`Ctrl+Shift+F`) | 채우기를 끄고 선만 남깁니다. 원본 픽셀을 보면서 경계를 확인할 때 |
| **외곽선 굵기…** | 기본 1.8. 줌과 무관한 화면 픽셀이라 확대해도 굵기가 일정합니다 |
| **채우기 투명도…** | 0(외곽선만) ~ 255(불투명). 기본 70 |
| **라벨 숨기기** (`H`) | 도형을 전부 잠깐 감춥니다 |

### 4.10 자동으로 세그먼트 만들기

손으로 다 찍지 않고 모델에게 먼저 시키는 방법이 셋 있습니다. **어느 쪽이든
결과는 "검수 대상"으로 저장됩니다** — 확인하고 `Ctrl+D` 로 확정하세요.

#### 학습한 모델로 자동 라벨링 (가장 실용적)

**도구 → 학습한 모델로 자동 라벨링…**

이 프로젝트에서 학습한 체크포인트(`runs/.../best.pt`)로 아직 라벨 없는
이미지를 채웁니다. **클래스가 붙은 채로** 나오므로 바로 쓸 수 있습니다.

1. 체크포인트를 고릅니다 (최근 학습이 위에 옵니다)
2. **신뢰도 임계값** — 높이면 정확하지만 놓치고, 낮추면 반대입니다 (기본 0.35)
3. **대상** — `라벨이 없는 이미지만` / `모든 이미지`
4. 실행 후 결과를 훑어보며 틀린 것만 고칩니다

> 100장 라벨 → 학습 → 나머지 자동 → 검수 → 재학습. 이 반복이 가장 빠릅니다.

#### 텍스트로 한 번에 (SAM 3 계열)

**[SAM]** 탭의 텍스트 칸에 `car` 처럼 입력하고 **[프로젝트 전체에 적용]**.
모든 이미지에서 그 개념을 찾아 현재 클래스로 추가합니다.

#### 전부 자동 분할 (클래스 없음)

**[SAM]** 탭의 **[이 이미지 전부 자동 분할]** / **[프로젝트 전체 자동 분할]**.
프롬프트 없이 찾을 수 있는 모든 영역을 나눕니다.

- **클래스를 알 수 없으므로 전부 현재 클래스로 들어갑니다.** 이후 도형을 골라
  클래스를 바꿔야 합니다 — 라벨링이라기보다 **후보 제안**입니다.
- 배경까지 하나의 영역으로 잡히는 경우가 많습니다. 필요 없는 것은 지우세요.
- SAM 1 / SAM 2 / Ultralytics 계열에서 동작합니다.

## 5. 기존 라벨 가져오기 → 세그먼트 변환

이미 검출용 박스 라벨이 있다면 처음부터 그릴 필요가 없습니다.

1. **파일 → 기존 라벨 가져오기 (Ctrl+I)**
2. **이미지 폴더** 와 **라벨 경로** 를 지정합니다.
   - 이미지 폴더가 지금 프로젝트와 다르면 그쪽으로 바꾸고 다시 스캔합니다.
   - 라벨 포맷은 자동 감지됩니다 — YOLO txt (det `cls cx cy w h` /
     seg `cls x1 y1 …`), COCO `instances_*.json`, Pascal VOC `*.xml`,
     LabelMe `*.json`. YOLO 클래스 이름은 `classes.txt` 또는 `data.yaml` 에서 읽습니다.
3. **[데이터 검증]** 을 누릅니다. 아무것도 쓰기 전에 이렇게 보고합니다:

   ```
   포맷: YOLO txt (detection / segmentation)
   프로젝트 이미지: 120장
   라벨 파일: 118개  ·  이미지와 매칭: 115개
   라벨 없는 이미지: 5장

   변환 가능한 박스: 430개

   짝을 못 찾은 라벨 (앞 3개):
     IMG_0007.txt, IMG_0031.txt, extra.txt
     → 파일 이름(확장자 제외)이 이미지와 같아야 합니다.
   ```

   리포트 아래에 **매칭된 이미지 한 장에 박스를 그려 미리보기**가 뜹니다.
   숫자가 맞아도 박스가 엉뚱한 곳에 있으면 좌표 규약이 다른 것이니, 여기서
   바로 알 수 있습니다.

   > 라벨은 **파일 이름(확장자 제외)** 으로 이미지와 짝지어집니다. 이름 규칙이
   > 다르면 폴더가 통째로 매칭되지 않으니, 여기서 먼저 확인하세요.
   > 매칭이 0이면 `가져오기` 버튼이 활성화되지 않습니다.
4. **[가져오기]** — 같은 라벨을 두 번 가져와도 중복되지 않습니다. 이미 있는
   것은 건너뛰고 `이미 있어 건너뛴 도형 N개` 로 표시됩니다.
5. 가져오면 **어떻게 변환할지 물어봅니다**:

   | 선택 | 동작 |
   |---|---|
   | **수동으로 하나씩** | `박스→세그먼트` 도구로 점선 박스를 클릭할 때마다 변환. 결과를 보며 진행 |
   | **현재 이미지 자동** | 지금 열린 이미지의 박스를 한 번에 |
   | **프로젝트 전체 자동** | 모든 이미지를 백그라운드로. 진행률이 표시되고 언제든 **[중지]** |
   | **나중에** | 박스만 두고, 나중에 [SAM] 탭에서 일괄 변환 |

6. 결과가 나쁘면 `Ctrl+Z` 로 되돌리고 클릭 프롬프트로 다시 잡습니다.

> 전체 변환도 이미지를 한 장씩만 메모리에 올립니다. 수만 장이어도 안전합니다.

### 7.1 분할 방식 — 비율로 나누기 / 원본 폴더 구조 유지

**분할 방식** 에서 둘 중 하나를 고릅니다. 기본값은 `비율로 나누기` 입니다.

| | 비율로 나누기 | 원본 폴더 구조 유지 |
|---|---|---|
| 기준 | 파일 경로 해시 | 이미지 경로의 `train`/`val`/`test` 폴더 이름 |
| val/test 비율 | 직접 지정 | 쓰지 않음 (입력칸이 흐려집니다) |
| 언제 쓰나 | 분할이 없거나 새로 나누고 싶을 때 | **기존 평가 셋을 그대로 지켜야 할 때** |

**비율로 나누기**

- 경로 해시로 배분하므로, 같은 프로젝트를 몇 번을 다시 내보내도 **같은 이미지가
  같은 분할에 들어갑니다.**
- `val 비율` 과 `test 비율` 을 각각 정하고 나머지가 train 이 됩니다.
  `test 비율` 을 `0.00` 으로 두면 train/val 두 갈래로만 나뉩니다.
- 대화상자 아래에 **예상 장수와 추천 비율**이 표시됩니다.
- 추천 비율(대략): 1천 장 미만 `val 0.20 / test 0.10` · 1천~1만 장
  `val 0.15 / test 0.10` · 1만 장 이상 `val 0.10 / test 0.05`.
  데이터가 많을수록 평가에 떼어 둘 비율은 낮아도 됩니다.

**원본 폴더 구조 유지**

- 이미지 경로에 이미 들어 있는 분할을 그대로 따릅니다. `images/train/…` 이든
  `train/images/…` 이든 인식하고, `valid`/`validation`/`testing` 같은 다른
  표기도 알아봅니다.
- 폴더 이름을 찾지 못한 이미지는 **train 으로 들어가며, 그 장수를 대화상자와
  완료 메시지에 표시**합니다. 조용히 묻지 않습니다.
- 프로젝트에 `train`/`val`/`test` 폴더가 하나도 없으면 실행을 막고
  `비율로 나누기` 를 쓰라고 안내합니다.

> **주의** — `비율로 나누기` 는 원본의 train/val/test 구분을 **무시하고 새로
> 나눕니다.** 원본 test 이미지가 train 으로 섞여 들어가므로, 기존 모델과
> 성능을 비교해야 한다면 반드시 `원본 폴더 구조 유지` 를 고르세요.

내보낸 파일 이름은 `images/train/x.jpg` → `images__train__x.jpg` 처럼 원래
경로를 `__` 로 이어 붙인 형태라, 어느 폴더에서 왔는지 나중에도 알 수 있습니다.

### 7.2 그 밖의 옵션

- **이미지 긴 변(px)** — 이미지를 줄여서 내보냅니다. **라벨 좌표도 같은 비율로
  함께 조정**되므로 그대로 학습에 씁니다. `0`(원본 크기)이 기본값.
  - 원본 이미지 폴더는 건드리지 않습니다. 내보낸 데이터셋만 작아집니다.
  - 지정값보다 이미 작은 이미지는 **늘리지 않습니다**.
  - 예: 800×600 이미지에 `320` → 320×240 으로 저장되고 박스도 0.4배로.
- **심볼릭 링크**를 고르면 디스크를 아낍니다(윈도우는 개발자 모드 필요, 실패 시 자동 복사).
  크기를 조정하면 파일을 새로 써야 하므로 이 옵션은 자동으로 꺼집니다.
- **검증 완료된 이미지만** 을 켜면 `Ctrl+D` 로 확인한 것만 나갑니다.
- **세그먼트 하나로 검출 라벨도 만듭니다.** `YOLO detection (bbox)` 를 고르면
  폴리곤의 바운딩 박스를 계산해 `cls cx cy w h` 로 내보냅니다. 박스를 따로
  그릴 필요가 없고, 같은 라벨에서 세그멘테이션용·검출용 데이터셋을 각각
  내보내면 됩니다.

## 8. 학습

**[학습]** 탭

1. 위에서 내보낸 데이터셋 경로가 자동으로 채워집니다.
2. 모델을 고르면 그 모델이 요구하는 데이터셋 포맷과 기본 하이퍼파라미터가 반영됩니다.
   패키지가 없으면 필요한 `pip install …` 이 안내됩니다.
3. `epochs / imgsz / batch / lr0 / workers / device` 를 조정합니다.
   - `device` 는 `0`(첫 GPU), `0,1`(다중 GPU), `cpu`
   - VRAM이 부족하면 `batch` 를 먼저 줄이세요.
4. **[학습 시작]** — 진행률·손실·지표가 실시간으로 표시되고 로그가 흐릅니다.
5. **[중지]** 로 언제든 멈출 수 있습니다. 결과는 `runs/<모델키>/<실행이름>/`
   (예: `runs/yolo11-seg/yolo11-seg_20260906_101530/`). 모델별로 묶여 있어
   같은 모델의 여러 학습을 비교하기 쉽습니다.
   **[결과 폴더]** 버튼으로 바로 열 수 있습니다.

> 실행파일 버전은 학습에 **외부 파이썬**이 필요합니다(용량 때문에 torch 를
> 넣지 않았습니다). **설정 → 학습용 파이썬 경로…** 에서 torch 가 설치된
> `python.exe` 를 지정하세요.

학습은 별도 프로세스라 라벨링을 계속하면서 돌려도 됩니다(단, GPU 메모리는 공유).
