# 새로운 분석·실험 전략

작성일: 2026-09-13 · 근거: [프로젝트 종합 분석](프로젝트_분석_20260913.md)

## 1. 목표와 원칙

목표는 가장 높은 숫자 하나를 얻는 것이 아니라 **원인을 설명할 수 있는 분석과 실제 사용 조건에서 재현되는 성능**을 확보하는 것이다. 현재 모델과 데이터는 기준선으로 활용하고, 효과가 확인되지 않은 고비용 실험은 순서를 늦춘다.

현재 사용 목적의 세부 조건은 명시돼 있지 않다. 아래 전략은 ‘7종 쓰레기 인식에서 객체 검출 품질, 배경 오탐, 처리 속도를 함께 관리하며 마스크 필요 여부는 별도로 결정’하는 것을 기본 가정으로 한다. 수치 기준은 확정 요구사항이 아니라 제안이며, 실험을 시작하기 전에 운용 목적에 맞게 고정해야 한다.

프로젝트 기존 원칙을 유지한다. GPU 학습은 한 번에 하나만 수행하고, 원본 백업은 읽기 전용으로 취급한다. 이번 작업에서 새 학습·라벨 수정·분할 이동은 실행하지 않았다.

## 2. 기존 전략에서 바뀌는 우선순위

| 기존 방향 | 새로운 방향 | 이유 |
|---|---|---|
| yolo26s에 배경을 넣으면 장점을 결합할 수 있다 | 배경 효과를 검증할 수 있는 같은 모델의 통제 실험 | 성능 유지·오탐 감소 폭은 아직 미측정 |
| plastic이 약하므로 해상도·P2부터 적용 | 출처×객체 크기별 실패 원인을 먼저 분석 | plastic test 객체 96.7%가 한 출처에 집중 |
| 사각형 6,678개를 우선 수정 | 4점 폴리곤을 층화 검수한 뒤 실제 오류만 수정 | 꼭짓점 수는 라벨 오류의 판정 기준이 아님 |
| 576 또는 512가 효율적 | 표본 편향을 고치고 실제 지연까지 측정 | 기존 속도는 batch 16 평균이며 전체 응답 시간이 아님 |
| test 결과로 다음 방법을 계속 선택 | 기존 test는 이력 비교용, val로 선택, 새 현장 holdout으로 확정 | 기존 test는 이미 전략 선택에 사용됨 |
| 클래스마다 10,000장으로 충분 | 독립 원본 그룹·출처·현장 조건의 다양성 관리 | general·battery의 출처와 증강 의존이 높음 |

## 3. 단계 0 — 결과 보존과 분석 도구 정비

**목적:** 새 실행이 기존 증거를 덮어쓰거나, 잘못된 지표로 다음 실험을 선택하지 않도록 한다. 학습 없이 진행할 수 있는 최우선 단계다.

### 해야 할 일

1. 완료 3개, 중단 세그 1개, 폐기 검출 시도 1개를 명시적으로 등록한다.
2. 결과별 `experiment_id`, `status`, 학습 시작·종료, parent checkpoint, 데이터 버전, seed, 평가 ID를 기록한다.
3. 새 학습은 고유 run 폴더만 허용하고, resume은 원래 run과 체크포인트가 일치할 때만 허용한다.
4. 손실 기록은 순서가 아니라 `box_loss`, `seg_loss`, `cls_loss`, `dfl_loss`, `l1_loss`, `sem_loss` 이름으로 저장한다. 없는 손실은 0으로 꾸미지 말고 해당 없음으로 둔다.
5. 세그의 best epoch는 실제 fitness 기준을 기록하고, 박스 최고·마스크 최고도 별도 열로 남긴다.
6. 완료 상태는 `summary.txt` 존재만으로 판단하지 않는다. 프로세스 종료 코드, 실행 ID, 완료 메타데이터, 체크포인트를 함께 확인한다.
7. 분할 검증기를 배경 이미지에 맞게 고치고, dry-run은 원본 인벤토리·이동 로그를 변경하지 않도록 한다.
8. 잠긴 의존성과 실제 환경을 대조하고, 직접 사용하는 패키지는 직접 의존성으로 선언한다.

### 결과물과 완료 조건

| 결과물 | 완료 조건 |
|---|---|
| 실험 목록 | 완료·중단·폐기가 구분되고 모든 가중치와 연결됨 |
| 정확한 지표 로그 | 원본 CSV와 첫·중간·마지막 에포크의 이름·값이 일치 |
| 안전한 run 관리 | 기존 run 이름으로 신규 실행 시 명확하게 차단 |
| 현재 분할 검사 | 두 데이터셋 모두 배경을 포함해 오류 없이 검사 |
| 원본 보존 | 기존 모델·CSV·보고서와 복구 인벤토리의 변경 없음 |

## 4. 단계 1 — 데이터와 평가의 기준 고정

### 4.1 현재 데이터를 v1 기준선으로 보존

현재 학습 모델은 현재 분할과 함께 묶어서 기록한다. 향후 평가를 편하게 하려고 기존 폴더의 test만 바꾸면 학습 자료가 평가에 들어갈 수 있다.

공통 인덱스에는 다음 필드를 둔다.

| 필드 | 내용 |
|---|---|
| sample_id | bbox/seg를 연결하는 공통 이미지 ID |
| image_path, bbox_label_path, seg_label_path | 실제 경로 |
| split_bbox_v1, split_seg_v1 | 현재 폴더 기준 분할 |
| class_names, instance_counts | 숫자 ID를 공통 이름으로 해석한 정답 |
| source_family, split_group | 출처와 독립 원본 그룹 |
| generated_augmentation, parent_group | 생성 여부와 가능한 원본 관계 |
| is_background, background_source | 배경 여부·출처 |
| image_hash, label_hash | 해당 버전의 실제 파일 해시 |
| annotation_version, review_status | 라벨 버전과 검수 상태 |

과거 매니페스트를 파괴적으로 갱신하지 않고 현재 상태 인덱스를 새 버전으로 만든다. 파일 경로 대신 ID를 실험 간 연결 기준으로 사용한다.

### 4.2 두 종류의 평가를 분리

- **동일 분포 평가:** 학습과 같은 서비스 범위에서 출처·클래스·크기·배경 비율이 대표적인지 확인한다.
- **새 출처/현장 평가:** 특정 장비·장소·날짜·출처를 통째로 분리해 일반화 성능을 본다.

무조건 출처 비율을 똑같이 맞추는 것도 정답은 아니다. 새 출처로의 일반화를 재려는 평가라면 출처 분리는 의도된 설계가 된다. 현재처럼 두 목적이 섞인 점수를 하나로 보고 원인을 단정하는 상태를 해소해야 한다.

### 4.3 증강본 처리

독립 표본 수는 증강 이미지 수와 별도로 집계한다. 향후 v2에서는 가능하면 **원본 그룹을 먼저 분할하고 학습 쪽에서만 증강**한다. 자연 이미지 평가와 증강 이미지 평가는 구분한다.

v2 분할을 만든다면 bbox와 seg에 동일한 그룹 할당을 적용하되, 기존 폴더를 이동하는 대신 새 목록·인덱스로 구성한다. 기존 모델을 v2 test에 평가할 때는 기존 train과의 교차 검사를 다시 해야 한다. 공정한 v2 학습 비교에는 양쪽 모델을 v2 기준으로 다시 학습해야 한다.

### 4.4 새로운 현장 holdout

기존 test는 이미 보고서와 전략 선택에 사용됐다. 기존 성능은 이력 비교로 남기고, 최종 성능 확인에는 아직 보지 않은 현장 자료를 확보한다.

- 촬영 장소·날짜·카메라·연속 영상 그룹 단위로 분리한다.
- 일반 장면, 작은 물체, 가림, 투명·반사 물체, 빈 장면을 포함한다.
- 실제 장면의 클래스 동시 출현과 목표 사용 환경을 보존한다.
- 배경 사진은 목표 쓰레기가 없는지 검수한다.
- 최종 후보와 confidence를 고정한 뒤 평가한다.

필요 표본 수는 목표 오탐률과 허용 불확실성으로 정한다. 150장만 보고 0%에 가까운 오탐을 보장하지 않는다.

## 5. 단계 2 — 새 학습 전 오류 분석

**목적:** 추가 학습 없이 어느 오류를 줄여야 하는지 확인한다. 여기서부터 모델 평가를 실행하되, 현재 단계의 선택은 val로 한다.

### 5.1 저장할 최소 예측 데이터

이미지별로 모델 ID, 데이터 버전, 설정, 정답 객체, 예측 클래스·confidence·박스, 세그 마스크, TP/FP/FN 매칭 결과를 저장한다. AP 계산용에는 낮은 confidence의 예측도 보존하고, 운용 confidence는 이후 별도 적용한다.

배경 오탐은 이미지 ID별 검출 목록을 남겨 모델들이 같은 사진에서 틀렸는지 확인할 수 있게 한다. 요약 수치만으로는 대응 비교와 사례 검수가 어렵다.

### 5.2 반드시 나눠 볼 항목

| 분석 단위 | 확인할 질문 |
|---|---|
| 클래스×출처 | plastic의 낮은 test AP가 특정 출처에서 반복되는가? |
| 클래스×박스 크기 | 같은 출처에서도 작은 객체를 더 놓치는가? |
| 클래스×밀집도 | 객체가 여러 개일 때 누락·중복 검출이 늘어나는가? |
| 원본/생성 증강 | general 성능이 증강본에 과도하게 의존하는가? |
| 배경 종류 | 천·반사·손·포장재·기계 부품 중 어디서 오탐하는가? |
| 라벨 품질 | 잘못된 class, 누락된 객체, 과한 박스, 잘린 마스크가 있는가? |
| bbox/seg 공통 test 교집합 | 공통 장면에서 경계 학습의 차이가 남는가? |

객체 크기는 기존 분석과 연결되도록 면적 비율 `<0.3%`, `0.3~1%`, `1~5%`, `>=5%`부터 사용한다. 이는 프로젝트용 구간이며 COCO의 공식 small/medium/large 정의와 혼용하지 않는다. 마스크 과제는 박스 면적과 실제 마스크 면적도 구분한다.

### 5.3 시각 검수 표본의 제안

아래 수량은 작업량을 제한하기 위한 제안이며 통계적 보장을 뜻하지 않는다.

- plastic의 주요 출처 2~3개에서 TP·FP·FN을 나눠 각각 표본을 검수한다.
- paper·battery의 4점 폴리곤을 출처·분할별로 나누어 클래스당 50~100개부터 본다.
- 생성 general과 자연 general을 각각 검수한다.
- confidence가 높은 배경 오탐을 우선 검수하고, 같은 배경에서 정상인 모델 결과와 나란히 비교한다.

오류를 ‘클래스 혼동 / 미검출 / 중복 / 위치 오류 / 배경 오탐 / 라벨 오류 / 판정 불확실’로 기록한다. 불확실 사례를 억지로 정답·오답으로 확정하지 않는다.

## 6. 단계 3 — 배경 효과를 검증하는 최소 실험

### 6.1 분석 질문

‘동일한 모델에서 배경 학습 이미지를 추가했을 때, 동일한 val에서 배경 오탐과 객체 재현율이 어떻게 바뀌는가?’를 묻는다.

| 항목 | A: 배경 제외 | B: 배경 포함 |
|---|---|---|
| 모델 | 동일한 yolo26s | 동일한 yolo26s |
| 초기 가중치 | 동일한 사전학습 체크포인트와 해시 | A와 동일 |
| 라벨 이미지 | 현재 bbox train 비배경 목록 | A와 동일 |
| 배경 학습 이미지 | 없음 | 현재 train 배경 2,400장 |
| val 객체 목록 | 공통 고정 목록 | A와 동일 |
| val 배경 목록 | 공통 고정 목록 | A와 동일 |
| imgsz / batch / workers | 640 / 16 / 4 기준 | A와 동일 |
| seed·증강·optimizer | 명시적으로 고정 | A와 동일 |
| 최고 모델 선택 규칙 | 공통 val 기준 | A와 동일 |

**기존 bbox_yolo26s_nobg를 A의 완전한 대체로 보면 안 된다.** 당시 val에는 배경이 없었고 그 기준으로 best.pt가 선택됐다. 기존 모델과 새 배경 포함 모델을 비교하는 것은 빠른 탐색적 비교로는 가능하지만, 배경 효과의 엄격한 통제 실험에서는 공통 val 규칙으로 A/B를 다시 맞춰야 한다.

같은 에포크 수에서는 B의 이미지와 업데이트 수가 늘어난다. 실용적 ‘배경 추가 효과’를 볼 때는 라벨 이미지 노출량을 같게 두고 추가 비용을 함께 기록한다. 연산량 자체를 통제하려면 총 optimizer step 또는 GPU 시간을 맞춘 보조 실험을 별도로 정의한다. 두 질문을 섞지 않는다.

### 6.2 후보 선택 기준

다음은 제안 기준이다. 실험 후 유리한 기준으로 바꾸지 않도록 실행 전에 고정한다.

- 공통 val의 배경 오탐이 감소할 것.
- 주요 클래스 recall이 미리 정한 허용 하락 범위 안에 있을 것.
- 객체 mAP50-95 하락도 허용 범위 안에 있을 것.
- 같은 recall에서의 배경 오탐 또는 같은 오탐 수준에서의 recall을 함께 볼 것.
- 총 학습 시간과 실제 운용 지연이 요구 범위 안에 있을 것.

예를 들어 전체 AP 절대 하락 0.01 이내, 핵심 클래스 recall 하락 0.02 이내 같은 기준을 검토할 수 있다. 이 값은 현재 측정 결과나 사용자의 확정 요구조건이 아니다.

같은 confidence 값은 모델마다 같은 운용 수준을 뜻하지 않을 수 있다. confidence 0.25·0.5 결과는 유지하되 threshold-recall-FP 곡선도 보고, 최종 threshold는 val에서 선택한다.

### 6.3 실행 비용 관리

기존 yolo26s 전체 학습 시간은 약 20시간 31분이다. 새 조건도 같은 시간이 걸리거나 오탐이 3%로 내려간다고 보장하지 않는다.

1. 소량의 대표 그룹으로 동작·메모리·로그를 확인한다.
2. 짧은 A/B 실험은 후보를 거르는 용도로만 사용한다.
3. 유망할 때만 전체 학습을 수행한다.
4. 모델 품질의 반복성을 주장할 필요가 있을 때는 여러 seed로 반복한다. 한 번의 실행은 단일 실행 결과로 보고한다.

초기 실험에서는 기존 기준을 따라 GPU 1개 작업, batch 16, workers 4, AMP, cache off를 사용한다. 다른 설정이 더 좋다고 검증된 경우에만 바꾼다.

## 7. 단계 4 — 실패 원인별 모델·데이터 개선

| 오류 분석 결과 | 먼저 할 대응 | 뒤로 미룰 대응 |
|---|---|---|
| 특정 출처에서만 plastic이 약함 | 그 출처의 라벨·촬영 조건 검수, 해당 분포의 학습 경험 보강 | 전체 해상도 일괄 상향 |
| 같은 출처 내에서도 작은 물체 FN이 높음 | 원본 해상도·작은 물체 라벨 점검, 대표 val에서 크기별 비교 | 근거 없는 클래스 분할 |
| 배경 오탐이 주 문제 | 검수된 hard negative 추가, threshold 조정 | 큰 모델로 무조건 교체 |
| 마스크 외곽선 오류가 주 문제 | 실제 오류 라벨 수정, 경계 사례 보강 | 4점 라벨 전체 삭제 |
| general이 증강본에서만 강함 | 새로운 자연 원본·현장 장면 추가 | 같은 원본의 증강 수만 증가 |
| 지연이 주 문제 | 실제 batch 1 측정, 적정 입력 크기 검증 | 학습 속도와 추론 속도의 혼동 |

hard negative는 목표 클래스가 **실제로 없는 이미지**여야 한다. 비닐처럼 보인다는 이유로 실제 비닐이 있는 이미지를 빈 라벨로 넣으면 잘못된 학습이 된다. 기존 test의 실패 이미지를 그대로 train에 편입하면 test를 재사용할 수 없으므로, 같은 실패 유형의 새로운 장면을 수집한다.

P2 구조, 고해상도 재제작, 타일링, 클래스 가중치, 오버샘플링은 각각 비용과 부작용이 있다. 실제 오류 분석으로 해당 가설이 지지될 때 한 항목씩 시험한다. P2가 현재 프로젝트의 최우선이라고 미리 확정하지 않는다.

## 8. 단계 5 — 해상도와 속도 검증 재설계

### 표본 추출

가능하면 전체 val을 사용한다. 소량 평가가 필요하면 출처·클래스·배경·독립 그룹을 고려한 표본을 한 번 뽑아 ID 목록으로 고정한다. 파일 이름 순서로 잘라 뽑지 않는다. 검출·세그의 분할이 다르므로 과제 내부 비교를 먼저 하고, 과제 간 비교는 공통 평가 설계를 별도로 적용한다.

### 비교 순서

1. 현재 640 모델의 정확도·지연 기준선을 측정한다.
2. 같은 모델·같은 목록에서 576, 512를 비교한다.
3. 운영 요구가 있을 때 480·320까지 넓힌다.
4. 추론 크기 조정만으로 충분하지 않으면 새 run에서 전이학습을 시험한다.
5. 전이학습 후 640 기준선보다 더 좋아질 것이라고 가정하지 않고 같은 평가로 검증한다.

### 속도 표에 반드시 넣을 정보

| 항목 | 기록 목적 |
|---|---|
| GPU, 라이브러리 버전, 정밀도 | 실행 환경 재현 |
| batch 1과 batch 16 | 단일 요청 지연과 처리량 분리 |
| 전처리·추론·후처리·전체 응답 | 서비스에서 실제 느린 구간 파악 |
| 워밍업 제외 여부, 반복 횟수 | 일회성 준비 비용 분리 |
| 중앙값과 p95 | 평균으로 가려지는 느린 요청 확인 |
| 정확도·클래스별 recall·배경 오탐 | 속도 향상의 품질 비용 확인 |

TensorRT는 추론 배포 후보가 생긴 뒤 필요할 때만 평가한다. 학습 시간 개선 단계에 넣지 않는다. 새 장비 구입이나 특정 배포 도구 도입은 이번 전략의 선행 조건이 아니다.

## 9. 결과 분석 체계

### 9.1 지표를 서로 다른 표로 분리

- 전체·클래스별 객체 AP/P/R.
- 세그 마스크 AP와 필요시 경계 품질 지표.
- 배경 이미지 오탐률, 이미지당 FP, confidence별 오탐.
- 출처·크기·밀집도·증강 여부별 성능과 표본 수.
- 학습 비용·추론 지연·모델 파일 크기.

오탐 이미지 개수를 mAP 열에 넣지 않는다. 지표마다 분모와 단위를 명시한다. 클래스 평균, 이미지 평균, 객체 가중 평균을 혼용하지 않는다.

### 9.2 불확실성과 비교

모델 A/B를 같은 이미지로 평가했다면 이미지별 대응 결과를 저장한다. 반복·유사 장면은 `split_group`을 bootstrap 단위로 묶어 차이의 불확실성을 추정한다. AP는 그룹을 재표집한 뒤 예측과 정답을 모아 다시 계산해야 한다. 단순히 ‘이미지별 AP’를 평균내지 않는다.

한 번의 해상도 실험에서 0.005 차이를 확인했다고 자동으로 유의미한 개선 또는 잡음이라고 단정하지 않는다. 평가 표본의 불확실성과 실행 조건의 변동을 따로 본다.

### 9.3 보고서 작성 규칙

모든 결론에 다음 네 요소를 붙인다.

1. 관측: 어떤 모델·목록·설정에서 무엇이 측정됐는가.
2. 범위: 해당 표본·출처·confidence에 한정되는가.
3. 해석: 원인이 확인됐는가, 가설인가.
4. 다음 판정: 무엇을 측정하면 가설을 유지하거나 버릴 것인가.

예: ‘배경 포함 모델에서 FP가 감소했다. 동일 모델의 통제 실험은 아니므로 배경만의 효과는 미확인이다. 공통 val에서 동일 초기 가중치의 A/B로 확인한다.’

## 10. 실행 우선순위와 단계별 종료 조건

| 순서 | 작업 | 새 학습 필요 | 다음 단계로 넘어가는 조건 |
|---:|---|---|---|
| 1 | 실험 상태·로거·표본 추출·검증기 정비 | 없음 | 기존 결과를 정확하게 읽고 안전하게 재실행 가능 |
| 2 | 출처·그룹·증강 메타데이터와 평가 목록 고정 | 없음 | 표본 대표성과 독립 원본 관계 설명 가능 |
| 3 | 기존 모델의 val 오류 분석·threshold 곡선 | 없음, 추론 필요 | 개선할 실패 유형과 목표 지표가 특정됨 |
| 4 | 같은 yolo26s의 배경 A/B | 필요 | 오탐 개선과 객체 품질 비용을 같은 평가에서 확인 |
| 5 | 확인된 라벨·출처·작은 객체 문제 개선 | 조건부 | 해당 문제의 지표가 개선되고 부작용 허용 가능 |
| 6 | 576·512 등 해상도·속도 절충 검증 | 추론 우선 | 실제 지연과 핵심 recall의 기준 충족 |
| 7 | 최종 현장 holdout 평가 | 보통 추론만 | 설정 고정 후 현장 요구조건 충족 |

마스크 사용 요구가 없으면 세그 대형 모델 재개를 우선할 이유가 적다. 마스크가 반드시 필요하면 seg_yolo11n을 기준선으로 두고 마스크 오류 분석부터 시작한다. 중단된 seg_yolo26s_nobg는 그 필요성이 확인된 뒤 재개 여부를 결정한다.

## 11. 완료된 산출물과 향후 작업의 구분

이번에 완료한 것은 종합 분석 보고서, 전략 문서, 전체 라벨·분할 감사와 그 재현 코드다. 위 단계의 로거 수정, A/B 학습, 예측 저장 체계, 신규 현장 데이터 확보는 **앞으로 수행할 작업**이다. 문서가 존재한다는 이유로 해당 기능이 이미 구현됐다고 해석하지 않는다.

현재 모델의 결과를 근거 있는 기준선으로 보존하면서, 가장 적은 실험으로 불확실성을 줄이는 것이 이 전략의 출발점이다.

## 12. 사용자 최종 방향 — 기존 모델에서 성능을 크게 높이는 추가 전이학습

사용자가 성능 유지가 아니라 **가중치의 실질적인 인식 성능이 훨씬 좋아져야 한다**고 정정했다. 이전 6,000장·성능 유지 중심 제안은 철회한다. 기존 best.pt를 출발점으로 활용하되, 한국 생활폐기물의 파손·찌그러짐·오염·재질·색·반사를 중심으로 학습 데이터를 보강한다.

첫 학습 예산은 train 약 12,000~20,000장을 탐색 범위로 두고, 예를 들어 15,000장 중 기존 대표 8,000장, 신규 또는 재검수한 어려운 이미지 5,500장, 검수된 배경 1,500장을 구성한다. **수량은 검증된 필요량이나 성능 보장이 아닌 제안**이다. 독립 원본·촬영 조건 수와 클래스별 실패 유형의 분포를 우선하며 증강 복제본을 새 자료로 세지 않는다. 현재 공개 수집분만으로 이 예산을 충족했다고 간주하지 않는다.

새 자료는 프로젝트 루트의 `01_datasets/finetuning_640`에서 관리한다. 상세 배출 기준과 진행 상태는 해당 폴더의 정책 문서·README·집계 JSON을 따른다. 미검수 원본을 학습 준비 완료 자료로 취급하지 않는다.

- 같은 모델 구조의 기존 best.pt로 새 미세조정 run을 시작한다. 완료된 학습의 resume과 구별한다.
- 640 해상도로 품질 개선부터 확인한다. 낮은 학습률과 짧은 후보 실험을 사용하되 10~20에포크 안에 충분히 개선된다고 보장하지 않는다. 동결은 비교 조건이며 필수 조건이 아니다.
- 기존 대표 자료를 함께 학습하여 특정 예외만 좋아지고 다른 품목은 나빠지는 현상을 확인한다.
- 성능 개선은 기존 모델과 새 모델을 같은, 수정된 정답으로 평가해 판단한다. 옛 정답으로 잰 점수와 새 정답으로 잰 점수의 차이는 모델 개선량이 아니다.
- 별도 한국 현장 평가 자료를 확보하고 깨진 유리의 glass 인식, 오염된 비닐의 vinyl 인식, 찌그러진 플라스틱의 plastic 인식을 따로 집계한다. 전체 AP뿐 아니라 상태별 recall·재질 혼동률·배경 오탐을 비교한다. 배출 규정은 학습 클래스에 반영하지 않는다.
- 속도는 전체 재학습 대신 대표 표본을 이용한 추가 학습으로 줄이는 방향이다. 같은 구조·같은 입력 크기라면 미세조정 자체가 추론 속도를 높이지는 않는다.

사진만으로 알 수 없는 내용물·정확한 수지·세척 가능성과 지자체 규칙은 모델이 모두 알아낸다고 가정하지 않는다. 재질·상태의 관측과 지역별 배출 정책을 분리하고, 미확정 조건은 추가 확인으로 연결한다. 이 목표를 충족하는 데이터가 충분한지는 클래스×품목×상태별 학습 곡선과 독립 평가로 판단한다.

### 라벨링 범위 최종 정정

사용자는 지역별 배출 안내를 앱에서 처리하며 오염된 비닐은 vinyl, 오염된 플라스틱은 plastic으로 유지하라고 명시했다. 따라서 깨진 유리도 glass로 유지하고, 배출 가능 여부로 general로 바꾸지 않는다. 모델은 기존 7개 재질·품목 그룹만 학습한다. 지역·오염별 수거함 선택이나 추가 상태 모델 개발은 이번 데이터 라벨링 범위가 아니다. 필수 라벨은 클래스와 객체 좌표이며 원본이 제공하는 상태 정보는 참고용으로만 보존한다.


## 최신 수정: 원본 보존과 YOLO 내장 증강 (2026-09-13)

이 항목이 앞선 640 우선 제안보다 우선한다. 오프라인 모자이크 학습 이미지를 만들지 않고 YOLO 내장 증강을 사용한다. 960 입력·mosaic 0.5를 주 후보로 준비하고, 같은 960에서 mosaic 0 및 640 기준 설정을 비교한다. detect/segment에는 classify 전용 dropout=0.1을 적용하지 않는다. 정확한 판단과 설정 경로는 ../KOREA_WASTE_RULES_20260913_v1/policy/YOLO_증강_Dropout_팩트체크_20260913.md에 기록했다. 설정 파서 검증만 완료했고 학습은 실행하지 않았다.

코팅된 종이 기반 제품은 paper, 천 수건은 general, 실제 필름은 vinyl이다. 화면에 표시된 종이·배터리 그림을 실제 객체로 라벨링하지 않는다. 배출 기준은 앱에서 별도 판단한다.


## 최종 사용자 확정: 640 전이학습

앞선 960 제안을 철회한다. 640×640 학습용 사본으로 변환하고 박스/외곽선 좌표를 함께 변환한다. JPEG 품질 85, optimize=True로 저장하고 EXIF·GPS·XMP·ICC·댓글 메타데이터를 제거한다. 원본과 별도 출처/라이선스 기록은 보존한다. best_train의 완료된 best.pt를 복사해 초기화하고 resume=False로 새 전이학습을 수행한다. 기존 자료를 클래스 균형으로 선별해 추가 자료와 섞고, 검증/시험 분할은 유지한다. 실제 혼합 수량과 속도는 새 reports 기록으로 확인한다.
