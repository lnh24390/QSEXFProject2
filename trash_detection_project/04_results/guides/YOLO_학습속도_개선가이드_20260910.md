# YOLO 쓰레기 분류 데이터 학습 속도 개선 가이드

작성일: 2026-09-10

## 1. 권장 방향

현재는 추가 이미지 압축보다 **배치 크기와 이미지 공급 속도를 조정하는 것**이 우선입니다. 설정 실험에는 클래스별 1,000장·5,000장 세트를 사용하고, 설정이 정해진 뒤 10,000장 세트로 최종 학습하는 방식이 전체 작업 시간을 줄이는 데 유리합니다.

이 문서는 확인한 PC 사양과 데이터 구성, 프로그램 기본 설정을 바탕으로 작성했습니다. 실제 학습에 사용한 모델명·실행 설정·에포크 시간은 확인되지 않았으므로 특정 병목이나 개선 배수를 단정하지 않습니다. 문서 작성 과정에서 학습 설정을 변경하거나 학습을 실행하지 않았습니다.

## 3. 이미지 압축과 학습 속도는 다릅니다

이번에 생성한 압축본은 이미지 용량이 약 **9.25GB에서 7.90GB로 14.6% 감소**했습니다. 그러나 표본 이미지 해독 검사에서는 압축본이 약 **18% 느렸습니다.**

- 검사 방식: 고정 표본 1,000장의 JPEG 데이터를 메모리에 올린 뒤 OpenCV로 해독, 순서를 교대해 3회 측정.
- 원본 중앙값: 약 3.00초.
- 압축본 중앙값: 약 3.54초.
- 이 수치는 디스크 읽기와 모델 계산을 제외한 표본 검사이며, 전체 학습 속도 측정 결과는 아닙니다.

파일이 작아져도 GPU가 계산하는 픽셀 수는 동일한 640×640입니다. 따라서 저장 공간 감소가 곧 학습 시간 감소로 이어지지는 않습니다. 속도 비교의 기준은 우선 **기존 비압축 10,000장 세트**로 잡으세요.

압축본은 손실 압축입니다. 이미지 품질 기준을 적용했지만, 모델 정확도가 동일하다는 것은 실제 검증으로 확인해야 합니다.

## 4. 우선순위 1: 배치 크기 조정

배치는 GPU가 한 번에 처리하는 이미지 수입니다. 너무 작으면 GPU의 처리 능력을 충분히 활용하지 못할 수 있습니다.

1. batch 8로 기준 시간을 기록합니다.
2. 나머지 설정을 유지하고 batch 16으로 비교합니다.
3. 16에서도 메모리 여유가 있고 처리량이 증가했다면 24를 추가 비교합니다.
4. 그래픽 메모리 부족 오류가 나면 배치를 낮춥니다.

RTX 4060 8GB에서 가능한 배치는 모델 크기와 검출·세그멘테이션 여부에 따라 달라집니다. batch 16도 모든 모델에서 가능한 것은 아닙니다.

배치를 두 배로 높인다고 시간이 절반이 되지는 않습니다. **초당 처리 이미지 수와 에포크 평균 시간**을 보고 결정하세요. 배치 변경은 학습 과정에도 영향을 줄 수 있으므로 최종 정확도를 함께 확인해야 합니다.

현재 프로그램 화면은 양의 정수 배치만 받습니다. GPU 메모리 비율을 뜻하는 `batch=0.8`이나 자동 배치 `-1`을 화면에 입력하는 방식은 지원하지 않습니다.

## 5. 우선순위 2: workers 조정

workers는 이미지를 읽고 학습용으로 준비하는 작업자 수입니다. 이미지 준비가 늦어 GPU가 기다리는 상황이라면 늘렸을 때 효과가 있습니다.

현재 CPU에서는 **4 → 8 → 12** 순서로 시험할 수 있습니다. 작업자가 많아질수록 RAM 사용량과 작업 간 경쟁도 증가하므로 가장 큰 값이 항상 가장 빠르지는 않습니다.

| 비교 단계 | batch | workers |
|---|---:|---:|
| 기준 | 8 | 4 |
| 배치 효과 확인 | 16 | 4 |
| 이미지 공급 효과 확인 | 앞에서 더 빨랐던 값 | 8 |
| 추가 비교 | 동일 | 12 |

한 번에 한 항목만 바꾸어야 어떤 변경이 효과가 있었는지 구분할 수 있습니다.

## 6. AMP는 켜두기

AMP는 일부 계산에 혼합 정밀도를 사용해 GPU 메모리와 연산 부담을 줄이는 기능입니다. 현재 프로그램 기본값은 켜짐입니다. 이미 사용하고 있다면 새롭게 얻는 개선은 없습니다.

배치·workers·AMP·캐시의 의미와 지원 값은 [Ultralytics 공식 학습 설정](https://docs.ultralytics.com/modes/train/)에서 확인할 수 있습니다. 프로그램 화면에서 지원하는 입력은 공식 라이브러리의 전체 옵션보다 제한적일 수 있습니다.

## 7. 캐시: 전체 RAM 캐시는 피하고 디스크 캐시는 측정 후 판단

JPEG 파일 크기와 RAM에 펼친 이미지 크기는 다릅니다. 학습 이미지 50,647장을 RGB 640×640 배열로 펼치면 이미지 자체만 약 **62.2GB**입니다. 검증 이미지와 프로그램·학습 준비 메모리는 별도입니다.

따라서 **RAM 32GB에서 전체 세트 RAM 캐시는 적합하지 않습니다.** 메모리가 부족해 디스크를 임시 메모리로 쓰게 되면 오히려 크게 느려질 수 있습니다.

### SSD 디스크 캐시

- JPEG를 매번 해독하는 부담이 큰 경우 도움이 될 수 있습니다.
- 학습·검증 이미지의 펼친 캐시에는 대략 71GB 이상의 추가 공간이 필요합니다.
- 확인 당시 C 드라이브 여유가 약 121GB이므로, 캐시 생성 후 학습 결과와 임시 파일을 위한 공간이 크게 줄어듭니다.
- 처음 캐시를 생성하는 시간은 별도로 듭니다.
- 디스크 읽기 자체가 병목이면 효과가 없거나 더 느릴 수 있습니다.
- 이미지 픽셀을 저장하는 캐시는 추가 JPEG 손실 압축과 달리 픽셀 품질을 낮추지 않습니다.

현재 프로그램 화면에는 캐시 선택 항목이 없습니다. 사용하려면 설정 전달 기능을 추가하거나 별도 학습 실행 방식이 필요합니다. `cache=True`는 RAM 캐시로 동작할 수 있으므로 디스크 캐시와 혼동하지 마세요.

### 작은 세트 RAM 캐시

클래스별 1,000장 세트는 학습 이미지 배열이 약 5.3GB이므로 실제 RAM 여유를 확인한 뒤 시험할 수 있습니다. 클래스별 5,000장 세트는 학습 배열만 약 29GB여서 RAM 32GB 환경에 여유가 부족합니다.

## 8. 전체 실험 시간을 줄이는 데이터 세트 활용법

| 클래스별 수량 | 실제 학습 이미지 | 권장 용도 |
|---|---:|---|
| 500장 | 2,077장 | 학습 실행·라벨·설정 오류 확인 |
| 1,000장 | 4,279장 | 모델과 설정의 빠른 비교 |
| 5,000장 | 23,640장 | 성능 경향 확인, 최종 후보 선정 |
| 10,000장 | 50,647장 | 최종 학습 |

5,000장 세트는 10,000장 세트보다 한 에포크에 처리하는 학습 이미지가 약 **53% 적습니다.** 실제 시간 감소율은 다르지만 반복 실험 비용을 크게 낮출 수 있습니다.

권장 순서는 다음과 같습니다.

1. 500장 세트로 학습이 정상 실행되는지 확인합니다.
2. 1,000장 세트로 모델·배치·workers 후보를 빠르게 비교합니다.
3. 5,000장 세트로 정확도와 학습 시간의 균형을 확인합니다.
4. 선정한 설정으로 10,000장 세트를 최종 학습합니다.

작은 세트의 결과가 전체 세트에서도 그대로 유지된다는 보장은 없습니다. 최종 후보는 전체 세트에서도 속도와 메모리를 확인하세요.

정확도를 비교할 때는 **같은 검증 이미지**를 사용해야 합니다. 수량별 세트는 서로 포함되는 관계이며 분할을 일관되게 구성했으므로, 10,000장 세트의 검증 자료를 공통 기준으로 사용하는 방식을 고려할 수 있습니다. 테스트 자료는 최종 평가용으로 남겨두세요.

전체 mAP50-95뿐 아니라 battery·general·vinyl 등 클래스별 재현율도 확인해야 합니다. 작은 세트 사용은 학습량을 줄이는 방법이므로 정확도 보존을 보장하지 않습니다.

## 9. 모델과 학습 길이 조정

현재 큰 모델을 사용한다면 같은 계열의 n 또는 s 모델을 비교할 가치가 있습니다. 작은 모델은 빠를 가능성이 크지만 복잡한 장면에서 정확도 차이가 생길 수 있습니다.

- 박스 검출이 목적이라면 박스 검출용 모델을 선택하세요.
- 사전학습 가중치에서 시작하면 처음부터 학습하는 것보다 적은 학습으로 유용한 성능에 도달할 수 있습니다.
- 에포크 수를 임의로 줄이기보다 검증 성능이 더 이상 개선되지 않는지 확인하고 조기 종료 설정을 활용하세요.
- 640 해상도를 낮추거나 증강을 대폭 줄이는 방법은 작은 배터리·얇은 비닐 인식 및 일반화 성능에 영향을 줄 수 있어 우선 적용하지 않는 편이 좋습니다.

관련 안내: [Ultralytics 공식 학습 최적화 가이드](https://docs.ultralytics.com/guides/model-training-tips/)

## 10. 속도 비교 방법

각 설정은 같은 데이터·모델·이미지 크기로 최소 3~5에포크 실행합니다. 첫 에포크의 준비 시간을 제외하고 나머지 평균 시간을 비교하세요. 캐시 생성 시간도 별도로 기록합니다.

| 기록 항목 | 이유 |
|---|---|
| 모델명·설정 | 비교 조건 재현 |
| 학습 구간 시간 | 검증 시간과 구분해 병목 판단 |
| 검증 포함 에포크 평균 시간 | 실제 완료 시간 판단 |
| 초당 처리 이미지 수 | 배치 크기가 달라도 처리량 비교 |
| GPU 사용률의 지속적인 변화 | 연산과 데이터 대기 구분의 단서 |
| 최대 GPU 메모리·RAM 사용량 | 안정성 및 여유 확인 |
| 검증 mAP50-95·클래스별 재현율 | 속도 향상에 따른 성능 변화 확인 |

GPU가 계속 높은 사용률을 유지하면 모델 계산 부담이 클 가능성이 있습니다. GPU 사용률이 반복적으로 떨어지고 CPU나 디스크가 바쁘다면 이미지 공급을 개선할 여지가 있습니다. 순간 사용률 한 번만으로 병목을 단정하지 마세요.

속도 비교 동안 다른 무거운 GPU·디스크 작업을 피하고 같은 조건을 유지하세요. 짧은 속도 시험만으로 최종 정확도를 판단할 수는 없습니다.

## 11. 첫 비교에 사용할 권장 설정

| 항목 | 시작 값 또는 절차 |
|---|---|
| 이미지 | 기존 비압축 세트 |
| 크기 | 640 유지 |
| 장치 | RTX 4060 GPU |
| AMP | 켜기 |
| batch | 8을 기준으로 16 비교 |
| workers | 더 빠른 배치에서 4와 8 비교 |
| 전체 RAM 캐시 | 끄기 |
| 디스크 캐시 | 데이터 공급 병목과 여유 공간 확인 후 별도 비교 |
| 초기 실험 데이터 | 클래스별 1,000장 세트 |
| 최종 학습 데이터 | 클래스별 10,000장 세트 |

**현재 우선순위는 배치·workers 최적화 → 작은 세트로 후보 선정 → 전체 세트 최종 학습입니다.** 정확도 손실 없이 몇 배 빨라지는 압축 방법은 이번 검사에서 확인되지 않았습니다. 같은 모델·640 해상도·전체 학습량을 유지하면서 GPU가 이미 충분히 바쁘다면 소프트웨어 설정만으로 가능한 개선 폭은 제한될 수 있습니다.
