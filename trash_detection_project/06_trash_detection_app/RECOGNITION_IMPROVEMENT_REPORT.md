| 플러그인 특성 | 네이티브 후처리가 **anchor 당 최고 점수 클래스 1개 + 클래스 무관 NMS** → 같은 물체의 다른 분류 후보가 앱에 오기 전에 사라짐 (사진 모드는 느슨한 NMS 후 앱에서 병합하도록 구현) |
| 추천 모델 | `lnh_10000_fp32` ≈ `trash_v11_e100_fp32` (test mAP50-95 0.714 / 0.709). `b8`·`b16` 은 0.52~0.54 로 크게 낮아 비교용 외에는 제외 권장 |

## 1. 평가 방법

| 항목 | 내용 |
|---|---|
| 평가 데이터 | `YOLO_7CLASS_10000_PER_CLASS_20260909` 의 test split 2,734장 중 무작위 500장 (박스 931개, 고정 시드) |
| 이미지 크기 | 500장 **전부 640×640** |
| 모델 형식 | `.pt` 로 평가. FP32 tflite 와 정확도가 같음을 별도 확인 (e100 0.709 = 0.709, lnh 0.714 = 0.714) |
| 환경 | WSL Ubuntu x86_64, ultralytics 8.4.146, torch 2.13 CPU, i7-13700. 속도(ms)는 PC CPU 기준 **상대 비교용** |
| 재현 | `python ml/scripts/eval_inference.py --weights <모델.pt> --data <data.yaml> --imgsz 640 800 960 --tta` |

**해석 시 주의할 한계**

1. 이미지가 640×640 이라 입력 800·960 결과는 "확대해서 넣은 효과"만 반영합니다. 실제 폰 사진(12MP)은 줄이는 폭이 작아져 디테일이 더 남으므로, 실사용 효과는 표와 다를 수 있습니다(대체로 더 유리할 가능성).
2. 클래스별 임계값을 **같은 test 로 고르고 같은 test 로 이득을 쟀기 때문에** 이득은 낙관적입니다. 별도 검증셋(또는 실제 폰 사진셋)으로 재확인이 필요합니다.
3. `b8`·`b16` 은 다른 데이터셋(클래스당 500·1,000장)으로 학습했습니다. 이 test 분할과 학습 이미지가 겹치는지는 확인하지 못했습니다(학습 val 점수와 test 점수가 비슷해 큰 누수는 없어 보임).
4. `e100`·`lnh` 는 학습 중 val 점수(0.835 / 0.782)가 이 test 점수(0.709 / 0.714)보다 높습니다. val 과 test 의 분포가 다를 수 있어, 학습 곡선 수치를 실사용 성능으로 보면 안 됩니다.

### 3-4. 해석

- **유리 누락(32~38%)은 모든 모델 공통이고 데이터 양과 무관**합니다. 투명·반사 재질의 한계일 수도 있지만, 20배 데이터에서도 변화가 없으므로 **유리 라벨 누락·박스 기준 불일치·유리 이미지 다양성 부족**을 먼저 의심해야 합니다.
- **플라스틱 누락과 비닐↔종이 혼동은 데이터가 많을수록 크게 줄었습니다.** 이 부분은 데이터 보강이 효과적입니다.
- 오검출(배경을 쓰레기로 잡음)은 **비닐·플라스틱**에 몰려 있습니다. 비닐·플라스틱 임계값을 너무 낮추면 오검출이 늘어나는 구조입니다.
- `lnh` 는 건전지(97.6%), `e100` 은 종이·비닐이 강합니다. 두 10,000장 모델의 강점이 다릅니다.

## 4. 측정 결과 ② 같은 가중치로 입력 해상도·TTA 만 바꿨을 때 (mAP50-95)

|---|---|---|---|---|---|---|---|
| b8 | 0.517 | 0.515 | 0.485 | **0.532** | 0.263 → 0.297 | 0.402 → 0.355 | 0.662 → 0.657 |
| b16 | 0.538 | 0.539 | 0.516 | 0.540 | 0.326 → 0.376 | 0.400 → 0.402 | 0.686 → 0.665 |

| lnh | 0.714 | **0.722** | 0.707 | 0.710 | 0.554 → **0.643** | 0.505 → 0.491 | 0.855 → 0.797 |

## 7. 인식률을 올리려면 추론 방식을 어떻게 바꿔야 하나 (재학습 없이)

1. **임계값을 하나로 쓰지 말고 모델별·클래스별로 쓴다.** — 네이티브에는 가장 낮은 기준을 넘겨 넉넉히 받고, 앱에서 클래스별로 다시 거른다. (구현)
2. **사진 모드에서는 플러그인 NMS 를 느슨하게 하고 앱에서 합친다.** — 플러그인은 anchor 당 최고 클래스 하나만 남기고 클래스 무관 NMS 를 하므로, 같은 물체의 다른 분류가 앱에 도착하기 전에 지워진다. IoU 0.9 로 받아 앱에서 사용자 IoU(기본 0.5)로 합치면서 비슷한 신뢰도의 다른 분류를 "또는" 후보로 남긴다. (구현)
3. **합친 뒤에 개수를 자른다.** — 합치기 전에 최대 개수로 자르면 같은 물체의 중복 박스가 자리를 차지해 다른 물체가 빠진다. (구현)
4. **사진 모드는 입력 해상도를 올린 별도 모델을 검토한다.** — 같은 .pt 를 `imgsz=800` 으로 재변환만 하면 되고, 플라스틱이 크게 오른다. 건전지 하락과 1.5~1.7배 시간은 사진 모드에서는 감수 가능. 실사진 비교 후 결정. (보류)
5. **물체를 크게 담게 한다.** — 크롭·줌·촬영 안내. 640 으로 줄어드는 폭을 줄이는 가장 확실한 방법. (미구현)
6. **TTA·초고해상도(960↑)는 쓰지 않는다.** — 측정상 이득이 없거나 손해. (결정)

## 9. 구현 내용 (① 과 ③)

### 9-1. ① 모델별·클래스별 신뢰도 임계값

| 항목 | 내용 |
|---|---|
| 값 위치 | `app/lib/config/app_config.dart` → `classConfidenceThresholds` (모델 파일명 → 클래스 → 값, 5장 표의 값) |
| 정책 | `app/lib/services/confidence_policy.dart` → `ConfidencePolicy` |
| 동작 | 네이티브(플러그인)에 `nativeThreshold` = 클래스별 기준 중 최솟값(및 전체 임계값 중 작은 값)을 넘기고, 앱에서 `accepts()` 로 클래스별 기준을 다시 적용. 목록에 없는 모델·클래스는 전체 임계값 사용 |
| 적용 범위 | 실시간 안내 패널, 사진 모드(박스·안내) |
| 모델 전환 | 모델을 바꾸면 그 모델의 값으로 자동 전환 (`onModelLoad` 에서 네이티브 값 재적용) |
| 설정 | 세부 옵션 설정 → "클래스별 신뢰도 임계값" 스위치(기본 켜짐, 저장됨). 켜져 있으면 현재 모델의 값 요약을 표시 |
| 알려진 한계 | 실시간 화면의 **네이티브 박스 오버레이**는 플러그인이 그리므로 최솟값(예: 0.24) 이상 박스가 모두 보임. 하단 안내는 클래스별 기준을 통과한 것만 표시 |

### 9-2. ③ 사진 모드 겹친 박스 정리 + "또는" 후보

| 항목 | 내용 |
|---|---|
| 발견 | 플러그인 `native-lib.cpp` 후처리: anchor 마다 최고 점수 클래스 1개만 남기고, `nms_sorted_bboxes` 가 **클래스 비교 없이** 겹친 박스를 제거 |
| 설계 | 사진 분석 시 플러그인에 IoU `AppConfig.photoNativeIouThreshold`(0.9)·최대 `photoMaxCandidates`(100)로 느슨하게 받음 → 앱 `refinePhotoResults()` 에서 클래스별 임계값 필터 → **클래스 무관 병합**(사용자 IoU 설정, 기본 0.5) → 최대 검출 개수로 제한 |
| 후보 조건 | 합쳐진 박스 중 **분리수거 분류가 다르고** 신뢰도 차이가 `AppConfig.ambiguousConfidenceGap`(0.15) 이하인 가장 높은 박스 |
| 표시 | 사진 박스 라벨 `종이/비닐? 70%`, 안내 카드에 `또는 비닐 → ○○ 일 수 있어요 (vinyl 62%)` |
| 코드 | `app/lib/services/photo_analysis.dart` (`mergeOverlapping`, `refinePhotoResults`, `summarizeDetections`), `photo_analyzer.dart`, `widgets/guide_panel.dart`, `widgets/photo_result_view.dart` |
| 범위 | 사진 모드만. 실시간은 네이티브 NMS 결과를 그대로 씀 |
| 한계 | 후보는 "인접 anchor 가 다른 클래스로 투표한 경우"에만 생김(한 anchor 안의 2순위 점수는 플러그인이 넘기지 않음). 수치(mAP)를 올리는 기능이 아니라 **잘못된 단정 안내를 줄이는** 기능 |
