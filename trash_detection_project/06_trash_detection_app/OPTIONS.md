# 옵션 설명서 — 어떤 값을 어떻게 정했고, 어디서 바꾸나

- 작성일: 2026-09-14
- 대상: 앱의 검출·안내 동작을 바꾸는 모든 설정값
- 요약: 기본값은 `app/lib/config/app_config.dart` 한 곳에 있고, 앱 화면에서 바꾼 값은 기기에 저장되어 기본값보다 우선합니다.

---

## 1. 값이 적용되는 순서

```
AppConfig (코드의 기본값)
    ↓  앱 첫 실행 / "기본값으로" 버튼
DetectionSettings (사용자가 바꾼 값, 기기에 저장됨)
    ↓
ConfidencePolicy (모델별·클래스별 임계값 적용)
    ↓
DetectionScreen → 플러그인(YOLOView / YOLO.predict)
```

- 앱에서 값을 바꾸면 **그 기기에만** 저장되고, 앱을 껐다 켜도 유지됩니다.
- 세부 옵션의 **"기본값으로"** 를 누르면 `AppConfig` 값으로 돌아옵니다.
- 코드의 기본값을 바꾸려면 `AppConfig` 를 수정하고 **다시 빌드**해야 합니다.

## 3. 어떻게 정했나

### 3-1. 측정으로 정한 값 — 클래스별 신뢰도 임계값

유일하게 **실측으로** 정한 값입니다.

- **데이터:** test 이미지 500장(박스 931개, 모두 640×640), 모델 4개에 동일 적용
- **기준:** 클래스마다 신뢰도를 0~1로 훑어 **F1이 최대가 되는 지점**
- **결과 예 (`0_bbox_yolo11n_100epoch_70000`):** 유리 0.24 · 건전지 0.36 · 플라스틱 0.37 · 비닐 0.45 · 캔 0.58 · 종이 0.60 · 일반 0.75
- **경향:** 종이·일반쓰레기는 높게(오검출 억제), 유리는 낮게(누락이 30~38%라 기준을 낮춰 건짐)
- **재현:**
  ```
  python ml/scripts/eval_inference.py --weights <모델.pt> --data <data.yaml>
  ```
  출력의 `app_config.dart classConfidenceThresholds:` 부분을 그대로 복사해 넣습니다.
- **주의:** 임계값을 고른 이미지와 효과를 잰 이미지가 같아 **낙관적인 수치**입니다. 실제 폰 사진으로 재확인이 필요합니다.
- 자세한 측정 결과는 `RECOGNITION_IMPROVEMENT_REPORT.md` 5장에 있습니다.

**측정 결과 (2026-09-15 기준, 앱 모델 16개 중 11개 측정 완료 · 모두 같은 test 500장)**

|---|---|---|---|
| `0_bbox_yolo26s_100epoch_70000` | **0.746** | 0.13 | YOLO26s, 36MB·PC CPU 50ms |
| `ain_yolov11n_epoch100_70000` | **0.736** | 0.29 | 10MB·PC CPU 18ms |

| `sj_bbox_yolo11n_300epoch_70000` | 0.706 | 0.34 | |

**전이학습 모델에 대한 해석** — 단계를 거듭할수록 꾸준히 좋아지지만(0.660 → 0.695 → 0.706 → 0.709),
최종본도 기존 상위 두 모델(`0_bbox_yolo26s` 0.746, `ain_yolov11n_epoch100` 0.736)에는 못 미칩니다.
현재 기본 모델과는 같은 수준(0.709)인데 **파일은 3.8배 크고(38MB vs 10MB) 추론은 3.5배 느립니다(62ms vs 18ms)**.
따라서 **기본 모델을 바꾸지 않았습니다.** 약점도 기존 모델들과 같아 유리(0.484)와 플라스틱(0.625)이 여전히 가장 낮습니다.

**측정하지 못한 모델 5개** — `0_seg_yolo11n_100epoch_70000`, `transfer_seg_stage1`, `transfer_seg_stage2`,
`transfer_seg_stage3_final`, `transfer_seg_final_rejected`. 세그멘테이션 평가에는 폴리곤 라벨이 있는 평가셋이
필요한데 현재 test 데이터는 박스 라벨뿐이라 ultralytics 가 거부합니다
(`Segment dataset requires equal numbers of boxes and segments`). 전체 임계값 0.45로 동작합니다.

### 3-1-1. ⚠️ 전체 임계값과 클래스별 임계값의 관계 (헷갈리기 쉬움)

**전체 신뢰도 임계값 슬라이더는 모델마다 다르게 작용합니다.** 규칙은 아래와 같습니다.

| 상황 | 앱이 실제로 쓰는 기준 | 슬라이더를 움직이면 |
|---|---|---|
| 스위치 **켬** + 측정값이 **있는** 모델 (현재 7개) | 그 모델의 클래스별 값 | **7개 클래스 판정에는 영향 없음.** 아래 "숨은 영향"만 있음 |
| 스위치 **켬** + 측정값이 **없는** 모델 (현재 `0_seg_yolo11n…`) | 전체 값 하나 | 모든 클래스에 그대로 적용 |
| 스위치 **끔** | 전체 값 하나 | 모든 모델·클래스에 그대로 적용 |

**숨은 영향 (측정값이 있는 모델에서 슬라이더를 내릴 때)**
앱은 플러그인에 "클래스별 기준 중 가장 낮은 값"을 넘겨 넉넉히 받은 뒤 클래스별로 다시 거릅니다.
슬라이더를 그 최솟값보다 **더 낮추면** 플러그인에 넘어가는 값도 함께 낮아져서:
- 실시간 화면의 **네이티브 박스가 더 많이 보입니다**(하단 안내는 클래스별 기준대로라 바뀌지 않음)
- 사진 모드에서 후보 박스를 더 많이 받아 계산량이 늘어납니다
슬라이더를 **올리는 것**은 측정값이 있는 모델에서 아무 효과가 없습니다.

**세부 옵션은 모델별로 저장되지 않습니다.** 하나의 설정을 모든 모델이 공유하므로,
seg 모델(측정값 없음)에 맞춰 슬라이더를 조정하면 다른 모델의 "측정값 없는 클래스"에도 같이 적용됩니다.

**목적별 권장 방법**

| 하고 싶은 것 | 방법 |
|---|---|
| 특정 클래스만 더 잡고 싶다 (예: 유리) | `AppConfig.classConfidenceThresholds` 의 해당 모델·클래스 값을 낮추고 재빌드. 앱 화면에는 클래스별 조정 UI가 없습니다 |
| 전체적으로 더/덜 잡고 싶다 | 스위치를 **끄고** 슬라이더 조정. 켠 상태로는 측정값이 있는 모델에 효과가 없습니다 |
| 모델끼리 성능을 비교하고 싶다 | 스위치를 **끄고** 같은 슬라이더 값으로 비교해야 조건이 같아집니다 |
| 측정값을 새로 반영하고 싶다 | `ml/scripts/eval_inference.py` 로 측정 → `AppConfig` 에 추가 → 재빌드 |

### 3-2. 플러그인 동작 때문에 정한 값 — 사진 모드 3종

플러그인 네이티브 코드를 확인해 정했습니다. 네이티브 후처리는 **anchor마다 최고 점수 클래스 하나만 남기고, 클래스 구분 없이 NMS**를 합니다.

| 값 | 이유 |
|---|---|
| 네이티브 IoU 0.90 | 기본값(0.5)으로 받으면 같은 물체의 다른 분류 박스가 앱에 오기 전에 지워져 "또는" 후보를 만들 수 없음 |
| 최대 후보 수 100 | 느슨하게 받은 중복 박스가 표시 개수(최대 30)를 밀어내지 않도록 넉넉히 |
| 후보 신뢰도 차이 0.15 | 종이↔비닐 혼동이 11~14%라, 확정해서 틀리기보다 후보를 함께 보여주는 편이 낫다고 판단 |

### 3-2-1. 세그멘테이션 표시 (마스크)

| 값 | 기본값 | 설명 |
|---|---|---|
| 세그 모델에서 박스도 그리기 | 끔 | 세그 모델은 **물체 모양을 따라가는 외곽선(스트로크)** 과 옅은 색칠로 표시합니다. 사각형 박스는 그리지 않습니다. 켜면 박스·라벨이 함께 나옵니다 |
| 마스크 외곽선 두께 | 2 | 마스크 격자(약 160×120) 기준 픽셀 수. 화면에서는 4~6배로 보입니다 |
| 마스크 확률 기준 | 0.50 | 이 확률 이상인 픽셀만 칠합니다. 낮추면 배경까지 번지고, 높이면 물체가 작게 보입니다 |
| 마스크 불투명도 | 0.45 | 낮추면 사진이 잘 보이고, 높이면 마스크가 선명해집니다 |

마스크 색은 **분리수거 분류 색**과 같고, 겹치는 부분은 신뢰도가 높은 검출이 이깁니다.

⚠️ **실시간 모드 제약** — 실시간 화면의 박스·마스크는 플러그인이 네이티브에서 그립니다.
플러그인에는 오버레이 전체를 켜고 끄는 기능만 있고 박스만 따로 끄는 기능이 없어,
"세그 모델에서 박스도 그리기" 를 꺼도 **실시간 모드에서는 박스가 계속 보입니다**(사진 모드에만 적용).
detect 모델은 마스크가 없으므로 이 설정과 무관하게 항상 박스를 그립니다.

### 3-2-2. 지역별 규칙과 상태별 안내 (데이터는 JSON)

두 기능 모두 **문구·규칙을 코드가 아니라 `app/assets/config/recycling_guide.json` 에 둡니다.**

**상태별 안내** (`categories[*].conditions`)
모델은 오염·코팅 여부를 판별하지 못합니다. 그래서 사용자가 눈으로 확인할 기준을 안내 카드에 함께 보여줍니다.
```json
"conditions": [
  {"when": "코팅되어 있거나 영수증(감열지)이면", "then": "general"},
  {"when": "스프링·테이프가 붙어 있으면", "note": "떼어내고 종이만 배출"}
]
```
- `when` = 상태, `then` = 그 경우의 카테고리 id(선택), `note` = 추가 안내(선택)
- 화면에는 "코팅되어 있거나 영수증(감열지)이면 → 일반쓰레기" 처럼 표시되며, 첫 번째 품목에만 최대 3줄 나옵니다.

**지역별 규칙** (`regions`)
```json
"regions": {
  "jeju": {
    "name": "제주특별자치도", "match": ["제주"],
    "notice": "클린하우스 중심, 품목별 배출 요일 확인",
    "categories": {"paper": {"bin": "...", "instruction": "..."}}
  }
}
```
- GPS 로 얻은 행정구역 이름(예: "제주특별자치도 제주시")에 `match` 문자열이 들어 있으면 그 지역으로 봅니다. **위에 적힌 지역부터** 검사합니다.
- `categories` 에 적은 항목만 공통 규칙을 덮어쓰고, 나머지는 공통 규칙을 그대로 씁니다.
- `notice` 는 안내 패널 맨 위에 지역 안내로 표시됩니다.
- 세부 옵션 → **지역** 에서 자동(GPS) 대신 특정 지역을 직접 고를 수 있습니다.

**지역 안내 읽기** — 안내 패널의 지역 문구를 누르거나, 세부 옵션 → 지역 → "이 지역 분리수거 안내 읽기" 를 누르면
지역 설명·품목별 규칙·출처 링크·확인 시점을 볼 수 있습니다.

⚠️ **요일·수거 방식은 지자체가 수시로 바꿉니다.** 특히 서울의 자치구별 배출 요일은 2022년 시행 안내 기준이고,
제주는 상시배출 시범 운영 여부에 따라 달라질 수 있습니다. 앱에도 확인 시점과 "거주지 공고로 최종 확인" 경고를 함께 표시합니다.

⚠️ **위치 판별 실패 시** 공통 규칙으로 동작합니다(권한 거부·위치 서비스 꺼짐·네트워크 없음). 주소 변환은 네트워크가 필요합니다.

### 3-3. 사용성으로 정한 값

| 값 | 이유 |
|---|---|
| 시작 모드 = 사진 | 실시간은 프레임마다 결과가 바뀌어 안내가 흔들립니다. 사진은 정지된 한 장을 분석해 결과가 고정되고, 후보 병합·"또는" 판정을 더 거쳐 정확도도 높습니다. 처음 쓰는 사람이 "찍어서 확인" 을 먼저 만나도록 했습니다. 모드는 저장하지 않으므로 앱을 다시 켜면 항상 사진 모드로 시작합니다 |
| 미리보기 박스 = 검은색·이름 없음 | 찍기 전에는 **어디가 잡히는지**만 보여주고, 무엇으로 인식했는지는 촬영 후 결과에서 처음 보여줍니다. 미리보기의 흔들리는 추측을 결과로 오해하지 않게 하려는 것입니다. 어두운 장면에서도 보이도록 반투명 흰 테두리를 한 겹 덧대 그립니다 |
| 전체 임계값 0.45 | 측정값이 없는 모델·클래스에 쓰는 대비용. 직접 0.50 → 0.45로 조정한 값 |
| IoU 0.50 | 객체 검출에서 흔히 쓰는 표준값 |
| 최대 검출 10 | 여러 개를 올려도 놓치지 않으면서 과하지 않은 수준 |
| 유지 시간 1.2초 | 한두 프레임 놓쳐도 안내가 깜빡이지 않게 |
| 갱신 주기 1.0초 | 프레임마다(초당 15~20회) 다시 그리면 글자가 계속 바뀌어 읽기 어려움 |
| 표시 품목 3개 | 첫 항목은 버리는 방법까지 보여주므로 3개면 화면을 덜 가리면서 충분 |
| 안내 패널 높이 200 | 안내 내용에 따라 패널 높이가 바뀌면 **위 카메라 화면이 줄었다 늘었다** 합니다. 높이를 고정해 카메라 영역을 항상 같게 유지하고, 내용이 넘치면 패널 안에서만 스크롤합니다 |

### 3-4. ⚠️ 지금은 효과가 없는 값

**카메라 해상도(720p)** — 현재 플러그인(ultralytics_yolo 0.6.14)이 이 값을 카메라에 전달하지 않습니다(소스 확인). 바꿔도 변화가 없습니다. 참고로 모델 입력은 어차피 640×640으로 줄어들어 해상도와 인식률은 직접 관계가 없습니다.

## 5. 값을 바꾸는 방법

1. **앱에서 (재빌드 불필요)** — 오른쪽 위 슬라이더 아이콘 → 모델 목록 아래 **세부 옵션 설정**. 바꾼 값은 기기에 저장됩니다.
2. **기본값 바꾸기 (재빌드 필요)** — `app/lib/config/app_config.dart` 수정 → `flutter build apk --release`. 이미 기기에 저장된 값이 있으면 **세부 옵션에서 "기본값으로"를 눌러야** 새 기본값이 반영됩니다.
3. **모델을 추가했을 때** — `ml/scripts/eval_inference.py` 로 측정해 `AppConfig.classConfidenceThresholds` 에 모델 이름(확장자 뺀 파일명)으로 추가. 추가하지 않아도 전체 임계값으로 동작합니다.
